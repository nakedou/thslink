# ThsLink-Cli（纯接口版）

本版只提供 HTTP 接口，无窗口、按钮、热键和图形渲染依赖。与桌面版共用交易、数据查询、请求编号关联及回执实现。当前版本为 v0.2.9，包含自动发现、严格验证、异步提交和下单回执修复。

本包与桌面版共用异步提交和原生任务回执通道。提交参数与同花顺自身 Python `cmd` 一致（`sync=0, source=0`），旧同步等待模式已移除。第一笔任务还在等待回执时可以提交后续命令；完整回执按各自请求编号更新。`native_task_id` 是内部任务号，不是券商合同号；`execution_done` 单独反映函数返回，原生关联任务未完成时仍不能卸载 DLL 或切换账户。字段与等待规则见包内 `使用说明.md` 或 [在线 HTTP 说明](https://github.com/electkismet/thslink/blob/main/docs/HTTP.md)。主程序和 DLL 须一起更新；服务端、虚拟机与本机使用相同后台链路，不依赖弹窗或 GUI 轮询。

## 使用

1. 整体解压，保持 `ThsLink-Cli.exe`、`thslink_bridge.dll`、`thslink-load.exe` 在同一目录。
2. 编辑同目录 `http-config.json`，先启动并登录同花顺交易端，再双击 `启动 ThsLink-Cli(点这个).bat`。
3. 成功启动后显示监听地址；用 Python 或其他 HTTP 客户端调用。关闭服务使用控制台 Ctrl+C。

双击 EXE 也会启动服务并显示控制台。需要先检查配置时执行 `ThsLink-Cli.exe --check-config`；指定另一份配置用 `ThsLink-Cli.exe --config "C:\路径\http-config.json"`。配置修改后重启生效，不读取桌面版 AppData 设置。

| 配置 | 默认 | 含义 |
|---|---|---|
| host | 127.0.0.1 | 监听 IP。局域网调用设为 0.0.0.0，并用服务器实际 IP 访问 |
| port | 8421 | 监听端口 |
| api_key | 空字符串 | 设置后所有接口均需 X-API-Key 请求头；日志不输出密钥 |
| terminal_path | null | 自动寻找交易端；有多个交易端时填写指定 xiadan.exe 的完整路径 |
| connect_bridge | true | 启动时连接交易端。false 只跳过启动连接，用于离线接口检查，不是禁止交易开关 |

当 `host` 是 `127.0.0.1` 或 `::1` 时，服务仅本机可访问。监听 `0.0.0.0`、局域网 IP 等非本机地址时，请设置强 API 密钥并配置防火墙；当前程序允许空密钥，空密钥会让网络可达的客户端无认证调用查询和交易接口。

启动时端口占用会在连接交易端前报错。交易端连接失败时 HTTP 仍可启动，`/health` 反映实际通道状态；交易端登录后输入 `3` 连接。桌面版与 HTTP 版共用单实例锁和 DLL 通道，同一会话内只能运行其中一个；重复启动会显示正在运行的产品、PID、版本和路径。旧版本无法提供身份时显示占用者未确认，不猜测 GUI/CLI。

## 控制台菜单和连接状态

输入编号或命令后按回车：`1` / `s` 查看状态，`2` / `h` 查看接口和 JSON 用法，`3` / `r` 连接交易端，`4` / `config` 设置接口，`5` / `review` 人工核对不确定结果，`0` / `q` 安全退出。菜单不会执行输入的买卖撤单命令。帮助中的交易 JSON 仅作示例。

状态显示监听地址、密钥是否设置、配置文件位置、DLL 连接状态和交易端 PID，不显示密钥内容。每 5 秒通过同一条 persistent-v1 命名管道读取 INFO 身份，连接或断线变化时输出；输入 `1` 可主动刷新。未完成交易、读取账户或通道锁占用时跳过探测，沿用上次结果；探测本身最多等待约 1 秒。此状态表示 DLL 通道可通信，不表示券商交易服务器一定可用。

`connect_bridge=false` 时不主动探测 DLL；输入 `3` 成功连接后启用监测。连接操作只加载或确认 DLL 并准备执行器，不强制卸载旧 DLL，也不重发历史委托。未完成请求期间拒绝连接操作。

菜单 `4` 按顺序设置监听地址、端口和接口密钥。回车保留原值，密钥输入 `-` 清空；任一步输入 `back` 取消且不写入配置。输入密钥会显示在当前控制台，请在自己的电脑上操作；密钥不会写入运行日志。设置非本机监听时菜单要求填写密钥。成功保存后输入 `0` 退出并重新启动；当前服务继续使用原配置，不会在设置过程中中断在途请求。交易端路径和启动连接开关仍通过配置文件设置。

## 接口与日志

接口路径和 JSON 契约与桌面版一致，详细说明见随包 `使用说明.md`。所有交易必须显式填写布尔 `notip: true`，批量逐笔填写。`http_demo.py` 的交易函数自动补齐该参数；直接运行示例只检查健康和账户。

运行状态和错误同时输出至控制台、EXE 同目录 `http-service.log`。超过约 2 MiB 时保留一份 `http-service.previous.log`，不记录请求业务内容。可选深层诊断仍使用既有 diagnostics 机制。

菜单 0/q 或 Ctrl+C 请求安全退出：先暂停新任务，再检查客户端与 DLL 的交易、回执、查询及账户操作；空闲时安全停止 DLL，并通过交易进程的模块列表确认 DLL 已卸载后退出。交易端本身继续运行。有未完成请求、未知结果、旧版 DLL 身份不可验证或卸载未确认时，安全退出被拒绝，程序显示原因及退出选项：输入 force（也可输入 f 或 1）立即强制退出 ThsLink 和 HTTP 服务；输入 back 继续运行。强制退出不关闭交易端、不强制卸载 DLL；DLL 可能仍驻留，未确认退出记录保留。退出不撤销已提交委托，也不自动重发。

结果不确定时，先在券商当日委托/成交中核对，再输入菜单 5，从列表序号选择待核对的记录，输入 `y` 确认。无需手填 DLL 请求编号或 local 编号。仅解除生命周期保护，原始回执保留，不伪造交易成功。原生提交调用、关联任务或查询仍未完成时，不能人工确认解除卸载保护。查询没有返回则需等待或自行确认后关闭交易端。

控制台右上角关闭、任务管理器强制结束、系统关闭或程序崩溃可能由 Windows 直接终止进程，不能保证执行安全卸载；推荐使用菜单 0/q 或 Ctrl+C。下次启动显示上次未确认退出的记录，实际是否残留 DLL 以身份/模块检查为准。退出或重启后进程内流水不会保留，调用方应保存请求编号、返回值及日志；结果不确定时禁止自动重发。

本版没有自动更新器、Windows 服务安装或后台守护。需要在登录同花顺的交互会话中运行，不能直接把它当作 Windows Session 0 服务。

## 编译

```powershell
cargo build --manifest-path ordertool/thslink/Cargo.toml --release --no-default-features --features http --bin thslink-http --locked
```

桌面版产品名称显示为 `ThsLink`；纯接口版产品名称为 `ThsLink-Cli（纯接口版）`。Cargo 内部构建 target 仍叫 `thslink-http`，安装包中的程序文件名为 `ThsLink-Cli.exe`。

桌面版使用默认 desktop 功能，构建时可指定 `--bin thslink`。DLL 和加载器继续复用同版本构建。打包运行 `ordertool/整理纯HTTP版.ps1`；默认生成本地测试包；正式发布由 `发布版本.ps1` 调用 `-Release`，两个版本共用已提交源码和同版本桥接组件。

## 兼容、权限与诊断

支持固定普通版 2026.07.02.0、2026.09.15.0 和远航版 2026.05.06.0，同时检查构建指纹；旧版与远航版限普通账户。其他构建或账户类型仍需验证。

v0.2.9 包含自动发现与严格验证。未知交易端构建须完整匹配三个已验证布局族之一，命令、嵌套账户字段、查询和任务回执契约全部通过且候选唯一才启用；任一项变化无法验证即拒绝。该机制不扩展两融账户或股票跟随支持。

启动和菜单 1 显示交易端文件版本、PID、路径和权限原因；文件版本读取不依赖 DLL 连接，能显示版本不代表已经兼容。连接前比较 ThsLink 与交易端权限；交易端以管理员运行而本程序权限普通时，应退出 ThsLink 后以管理员身份运行。程序不自动提升权限。

`ThsLink-Cli.exe --check-terminal` 只输出版本和权限信息，不取得单实例锁或加载 DLL。HTTP /health 的 terminals 返回同样元数据。诊断开关为程序目录或本地用户 ThsLink 诊断目录中的 `diagnostics/enabled` 标记；技术日志按大小轮换，记录调用与通信阶段，不作为券商成交凭据。

HTTP 的 batch_id 自 v0.2.8 起为 GUID 字符串，请原样保存。批次 complete 仅表示成员完整，不表示全部成功；回执查询错误不等于原订单拒绝。

当前异步实现中，正常异步任务没有即时回执不会阻挡后续提交；30 秒超时后仍按原编号跟踪。提交前检查、行情读取、锁或分发本身若卡住，后续新单仍可能被串行保护挡住。未完成和不确定请求达到容量上限时会拒绝新请求。超时不取消委托，不自动重发或重启交易端。v0.2.9 还修复旧等待状态覆盖明确回执、任务释放时误用部分返回、批量提示换行破坏记录边界等问题。
